Installation & Global Setup

You can execute MountX directly using the standalone binary or set up the global symlink:

Terminal — Setup Symlink
# 1. Run directly using the native Linux executable
./mountx-native host/fbtest.mx

# 2. Or symlink mountx to your local bin path
ln -s "$PWD/mountx" ~/.local/bin/mountx

# 3. Verify version
mountx --version
# Output: MountX 1.1.0  (c) 2026 Ziad Mohsin

💻 CLI & Execution Modes

MountX provides three flexible modes of execution via the command-line interface:

Command Mode Description
mountx program.mx Script Mode Executes the specified .mx file from top to bottom.
mountx Interactive REPL Opens real-time interactive shell. State and variables persist across inputs.
mountx -e "printx(1+1)" Inline Evaluation Evaluates one-line snippets instantly without requiring a script file.
mountx --selfhost program.mx Self-Hosted Mode Executes the program through selfhost/interp.mx for parity verification.
./mountx-native app.mx Native Engine Direct execution on the high-performance compiled C substrate (5x-20x faster).

📦 mxpm — The Official Package Manager

mxpm is MountX's official project and package manager. It manages project manifests (mountx.json), installs libraries into libs/, packages distributable .mxpkg tarballs, and launches the in-browser WebAssembly playground.

Terminal — mxpm Commands
# Initialize a new project
mxpm init my-app

# Install a dependency
mxpm add json-utils

# Run project lifecycle scripts (from mountx.json)
mxpm run start
mxpm run test

# Launch the in-browser WebAssembly IDE playground
mxpm playground

✍️ Syntax & Core Basics

MountX source files are optionally enclosed within mountx and unmountx blocks (auto-wrapped if omitted). Variable declaration uses let, and comments start with #.

MountX — Variables and Operators
mountx
# Declare variables with let
let message = "Hello, MountX!"
let count = 42
let pi = 3.14159

let empty_val = nullx

# Reassignment does not use 'let'
count = count + 10

# Console output
printx(message)

unmountx

Arithmetic Division Invariant

In MountX, standard division / always returns a floating-point number (7 / 2 == 3.5). If you need truncated integer division, use the built-in native function idiv(a, b) (idiv(7, 2) == 3).

🔄 Control Flow

MountX features standard if / else if / else branching, while loops, fixed iteration loop N, and modern collection loops for in.

MountX — Branching and Loops
mountx

let score = 85

    printx("Grade: A")
} else if score >= 80 {
    printx("Grade: B")

    printx("Grade: C")

⚡ Functions & Scopes

Functions are defined using the func keyword. Functions without an explicit return statement evaluate to nullx.

MountX — Functions & Recursion
mountx

    return a * b
}

# Recursive Fibonacci
func fib(n) {
    if n <= 1 {
        return n
    }
    return fib(n - 1) + fib(n - 2)
}

printx("12 * 5 = " + multiply(12, 5))
printx("fib(10) = " + fib(10))

🧱 Classes & Object-Oriented Programming

MountX provides full object-oriented programming with single inheritance (extends), explicit constructor initialization (init), field defaults, instance referencing via this, and multi-level superclass calls via super.

MountX — Classes & Polymorphism
mountx
classx Account {
    let owner = ""
    let balance = 0.0

    func init(owner, initial_deposit) {
        this.owner = owner
        this.balance = initial_deposit
    }

    func deposit(amount) {
        this.balance = this.balance + amount
        return this.balance
    }

    func summary() {
        return this.owner + ": $" + this.balance
    }
}

classx SavingsAccount extends Account {
    let interest_rate = 0.05

    func init(owner, deposit, rate) {
        super.init(owner, deposit)
        this.interest_rate = rate
    }

    func apply_interest() {
        let interest = this.balance * this.interest_rate
        this.deposit(interest)
    }
}

let acc = newx SavingsAccount("Alice", 1000.0, 0.05)
acc.deposit(200.0)
acc.apply_interest()
printx(acc.summary())
# Output: Alice: $1260.0
unmountx

🛡️ Error Handling & Exceptions

Errors can be thrown with throwx and intercepted using tryx { ... } catchx (err) { ... }. Thrown values maintain their original type (strings, integers, arrays, or custom class instances).

MountX — Exception Handling
mountx
func fetch_record(id) {
    if id <= 0 {
        throwx "InvalidIDError: ID must be positive"
    }
    return ["id", id, "status", "active"]
}

tryx {
    let rec = fetch_record(-5)
    printx(rec)
} catchx (e) {
    printx("Handled exception: " + e)
}
unmountx

🌐 Full-Stack Web Engine

MountX includes a production-grade HTTP/1.1 server framework (http_server.mx) with express-like route registration, URL pattern matching (:id), middleware cascading, and static file serving.

MountX — HTTP Web Server & REST API
mountx
importx http_server

let app = http_server.new_app()

# 1. Global Request Logger Middleware
app.use(func(req, res) {
    printx("[HTTP] " + req.method + " " + req.path)
    return true
})

# 2. REST API Route with parameter matching (:id)
app.get("/api/users/:id", func(req, res) {
    let user_id = req.param("id")
    res.json([
        ["user_id", user_id],
        ["status", "active"],
        ["server", "MountX 1.1.0 Native"]
    ])
})

# 3. HTML Welcome Page
app.get("/", func(req, res) {
    res.html("<h1>Welcome to MountX Web Engine!</h1>")
})

printx("🚀 Starting server on http://127.0.0.1:8080")
app.listen(8080, "127.0.0.1", nullx)
unmountx

⚙️ C99 Substrate Engine Architecture

MountX compiles from a 100% self-hosted interpreter (selfhost/interp.mx) into optimized C99 source (gate2/g1/interp.emitted.c) and links against the substrate floor (mini.c).

Tagged Value Struct (MxValue)
16-byte aligned tagged unions with CPU-register arithmetic bypass for integers, floats, and booleans.
Recycled Environment Frames
Scopes up to 8 variables allocate on an inline stack-like buffer (small_b[8]) and recycle via g_env_freelist in O(1) time.
Small Array Inline Buffers
Arrays with ≤ 2 elements use inline buffers (small_v[2]), eliminating heap allocations for boxing.
Symbol Table Interning
Identifiers and dictionary keys are interned into canonical pointers, enabling O(1) direct pointer comparison.
